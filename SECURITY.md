# Security Policy

## Reporting a Vulnerability

We take security seriously. If you discover a security vulnerability, please follow these steps:

### Do Not

- **Do not** open a public GitHub issue for security vulnerabilities
- **Do not** discuss the vulnerability publicly until it has been addressed

### Please Do

1. **Email** the security team with details of the vulnerability
2. **Include** steps to reproduce the issue
3. **Provide** any relevant logs or screenshots (redact sensitive data)
4. **Wait** for acknowledgment before public disclosure

### What to Expect

- **Acknowledgment** within 2 business days
- **Assessment** of the vulnerability within 5 business days
- **Regular updates** on progress toward a fix
- **Credit** for responsible disclosure (if desired)

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| 1.x.x   | :white_check_mark: |

## Security Best Practices

When using this service:

- Keep dependencies up to date
- Use strong secrets and API keys
- Enable HTTPS

## Known Security Considerations

- All endpoints should be behind appropriate authentication
- Database credentials should be securely managed
- Logs should not contain sensitive information


Thank you for helping keep this project secure!
